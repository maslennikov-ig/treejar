## Проверка покрытия без изменения склада

В 06:05 UTC read-only diagnostic использовал существующий cached token и
Redis GET. Выполнено **5 Inventory GET: 4 HTTP200 + 1 HTTP401**. Последний
запрос — `/inventoryadjustments`. После 401 диагностика остановилась: без
OAuth refresh, повторных запросов, расширения доступа, записей или сообщений.
Причина 401 не установлена; не выдаём её за доказанную ошибку scopes.

Запрос `/items` с `last_modified_time=2026-10-03T06:05:44+0000`, сортировкой
по времени и размером страницы 3 вернул 9 различных позиций за три страницы.
Их возвращённые `last_modified_time` лежат между 18 марта и 7 июля 2026,
то есть раньше запрошенной границы. Список остался незавершённым после
предусмотренного лимита страниц. Отдельная выборка с сортировкой D вернула
item timestamps 2 октября.

Эта неоднозначность **не доказывает, что складская операция была пропущена**:
время поля и семантика фильтра могут различаться. Она также не позволяет
считать HTTP200 доказательством пригодности фильтра. Нужны привязанные к
операциям наблюдения и объяснение семантики. Полный непустой delta, равные
timestamps и устойчивость страниц live не подтверждены.

Проверенные ранее bulk sizes 1/2/4/8 остаются нижней проверенной границей,
не максимумом endpoint. Runtime bulk override=0; точечные свежие ID GET
работают без предположения о размере пачки. Catalog scoping выключен.

| Статус | Значение | Доказательство / условие |
|---|---|---|

| provider_coverage_verified | false | История операций недоступна (401); причинного stock/delta proof нет |
| live_activated | false | Delta off, coverage evidence пусто |
| live_24h_measured | false | Окно 15h полного режима; нужны сутки после доказанного включения delta |

Чтобы закрыть AC02 без изменения склада, нужны доступные только на чтение
данные или обезличенная история обычных операций: отгрузка, приход,
корректировка, возврат/отмена и перенос, если он меняет `stock_on_hand`.
Для каждого наблюдения нужны стабильная анонимизированная item identity,
UTC-время операции, количество до/после и соответствующий результат
modified-since. Создание, редактирование/SKU rename, деактивация и удаление
также должны иметь наблюдаемую историю; hard delete может подтверждаться
ежедневным full. Неотражённые в истории типы остаются непроверенными.
Один sales order или текущий остаток не заменяет такое доказательство.

Read-only API history существующему токену недоступна. По последующему запросу
владельца подготовлен отдельный доступ только на чтение, описанный ниже;
выдача токена требует входа владельца и согласия в Zoho. Существующий доступ не менялся.
До получения данных безопасное состояние — действующий полный опрос.
После доказательства покрытия остаются разрешённое включение delta и реальное
24h окно. Задача не закрыта; имитация 157 вызовов/сутки остаётся моделью.

## Восстановление

Delta уже выключена. Для отката будущей активации вернуть full fallback,
пересоздав только app/worker по разрешённой доставке. Сохранить v2/legacy,
ARQ, env/allowlists и customer state; не очищать Redis или складские данные.
Полный режим увеличивает расход API, как показывает реальное окно выше.

## Продолжение: отдельный доступ к истории только на чтение

После запроса владельца продолжить выполнен один дополнительный cached-token
GET в **10:06:08 UTC / 13:06:08 МСК**. Ответ **401, Zoho code57,
not_authorized**. После него остановка, без retry/refresh/Redis-записей.
TTL кэшированного токена2632с — локальные метаданные, не доказательство его
валидности у провайдера. Старые инструкции выдачи токена не содержат history
READ scopes; scopes и ограничения роли пока не разграничены.

Рабочий OAuth client используется также CRM. Подготовлена отдельная выдача
через **новый EU server-based client**: только шесть READ scopes, online grant
до часа, без refresh token. Client ID/secret вводятся в локальную форму;
рабочий клиент не редактируется и не отзывается. Парольный ввод, строгие
Host/Origin/CSRF/state guards, один обмен кода, запрет повторов и сохранение
токена в600 файле вне Git реализованы. Форму проверено из Windows: HTTP200,
no-store, password input и нужный callback. Это проверка локальной связи;
визуальная проверка страницы и live OAuth consent пока не подтверждены.

Готов runnable `history-grant-probe.py`: проверяет права/срок локального токена,
передаёт его через SSH stdin и использует неизменённую SHA-pinned диагностику.
Перед HTTP проверяет рабочую организацию и EU API host. Лимит16 GET,
последовательно, с остановкой по cooldown/401/429; без token swap, env/Redis
записей, обновления склада и сообщений. Без токена подтверждён выход с
`remote_started=false`, `inventory_requests=0`.

**17 локальных проверок прошли**: OAuth/provider/SSH transport перехвачен,
не является live-доказательством. Новые entrypoints включены в source footprint
текущей slice acceptance; прежний runtime release footprint не меняется.
Команды, точные scopes/callback, hashes и receipts:
`docs/research/2026-10-04-zoho-stock/README.md`.

**Недостающий шаг — вход владельца в Zoho API Console и согласие на отдельный
доступ.** Live OAuth обмен не выполнялся, нового токена ещё нет. Склад и
production credentials сохранены. После доступа всё ещё требуется причинное
доказательство обычных операций: доступная история сама по себе не закрывает
неизвестное покрытие AC02. Delta и заявление об экономии остаются выключены.
